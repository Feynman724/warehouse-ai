# 物资仓库 AI 借还工作台 v2

线上地址：<https://blog.oppenheimer123.xyz/warehouse-ai/>

本项目希望用“同框拍照 + AI 识别 + 申请清单比对”代替借出时逐件人工清点。借还照片同时作为交接记录；核验通过后，库存按物资逐项更新。当前通用模型尚不能可靠识别用户提供的混放校园物资照片，实际借还仍需管理员复核；预标注样例仅用于演示交互。

作品介绍：[PDF](output/pdf/作品介绍文档.pdf) · [LaTeX 源文件](output/pdf/作品介绍文档.tex)

## 功能

- SQLite 服务端共享数据；
- 同框借还：一笔申请可包含多类物资，获批后把全部物资放在同一区域拍一张照片；照片、申请清单、AI 建议、复核数量与逐项库存变动关联留痕；
- 同框借出在模型覆盖全部物资、数量完全一致、画质通过且每项置信度至少 75% 时才自动扣减所有库存；任一项不确定则整单进入管理员复核，归还始终由管理员确认；
- 整理用户提供的 23 张单品照片为 10 类物资参考样本，登录后可在同框借还页查看，辅助拍摄和人工复核；样本不等于训练完成的识别模型；
- 使用用户提供的“喇叭 + 麦架”同框实拍制作三步交互演示：样例预标注框、识别清单、沙盒库存变化。页面明确标注这是演示，不修改真实库存，也不冒充实时模型识别；
- 用户绑定联系电话、10 位学号、行政班级与部门；
- 拒绝理由必填且申请人可见；
- 管理员可在借还开始前修改审批决定，所有决定留痕；
- 管理员电话集中配置；
- 手动拉黑、解除、阻止申请、用户申诉与管理员处理；
- 借出及归还复核；
- 借还照片留痕、管理员影像档案与借出 / 归还画面对照；
- YOLOv5n 本地目标检测、常见物资数量映射、申请清单核验和画质提示；
- 无需已有申请即可进行不改库存的视觉试拍，方便现场演示；
- 借还照片入库前统一压缩并去除原始 EXIF 信息；
- 模型不支持的物资、画质异常或清单差异进入人工复核，不直接改库存；
- 借出照片在画质通过、识别数量与申请一致且最低置信度达到 75% 时自动扣减库存；归还仍需人工确认；
- 管理员新增、编辑、停用物资，增减库存并记录原因及前后数量；
- 归还时报损或丢失，管理员复核后自动更新可用及缺损库存；
- systemd 常驻运行，Nginx 反向代理。

## 服务器

```bash
ssh sever1
sudo systemctl status warehouse-ai
sudo journalctl -u warehouse-ai -f
```

部署位置 `/opt/warehouse-ai`，共享数据库 `/opt/warehouse-ai/shared/warehouse.db`。

视觉模型使用 [Ultralytics YOLOv5n ONNX](https://github.com/ultralytics/yolov5/releases/tag/v7.0) 的 COCO 类别。系统虽配置了桌、椅等通用类别映射，但用户提供的 10 类单品参考照在当前阈值下均未产生可映射检测；因此不能把现有照片视为已具备自动识别能力。帐篷、喇叭、线材等校园专有物资仍需管理员人工确认。照片差异仅是复核线索，不能据此自动判定损坏。模型和 Python 依赖分别位于服务器的 `/opt/warehouse-ai/yolov5n.onnx` 与 `/opt/warehouse-ai/vision-venv`。

2026-10-16 对用户提供的 8 张混放场景照片进行现有模型测试：8 张均未检出可映射的物资。它们作为当前版本的真实场景基线；不能把单品参考照片直接当作同框识别已达到可自动扣库存的证据。后续需要混放照片的逐物体标注和独立验证集，才能训练或评估仓库专有类别模型。
