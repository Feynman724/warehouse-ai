# 物资仓库 AI 借还工作台 v2

线上地址：<https://blog.oppenheimer123.xyz/warehouse-ai/>

本项目希望用“同框拍照 + AI 识别 + 申请清单比对”代替借出时逐件人工清点。借还照片同时作为交接记录；核验通过后，库存按物资逐项更新。网页支持打开摄像头持续识别，也支持上传实拍照片走同一模型。当前模型对混放物资仍有漏检和误认，实际借还仍需管理员复核，不会凭实时预览自动扣库存。

作品介绍：[PDF](output/pdf/作品介绍文档.pdf) · [LaTeX 源文件](output/pdf/作品介绍文档.tex)

## 功能

- SQLite 服务端共享数据；
- 同框借还：一笔申请可包含多类物资，获批后把全部物资放在同一区域拍一张照片；照片、申请清单、AI 建议、复核数量与逐项库存变动关联留痕；
- 当前开放词表模型的识别结果只作候选建议；管理员核对实物、照片和申请清单后逐项入账，归还也由管理员确认；
- 整理用户提供的 23 张单品照片为 10 类物资参考样本，登录后可在同框借还页查看，辅助拍摄和人工复核；样本不等于训练完成的识别模型；
- 摄像头画面连续送入本地 YOLOE-26s 与用仓库实拍图微调的 YOLO11n，返回真实候选框与物资清单；红色喇叭额外使用实拍视觉提示。预览不修改库存；
- 用户绑定联系电话、10 位学号、行政班级与部门；
- 拒绝理由必填且申请人可见；
- 管理员可在借还开始前修改审批决定，所有决定留痕；
- 管理员电话集中配置；
- 手动拉黑、解除、阻止申请、用户申诉与管理员处理；
- 借出及归还复核；
- 借还照片留痕、管理员影像档案与借出 / 归还画面对照；
- YOLOE-26s 与仓库专用 YOLO11n 本地目标检测、物资数量候选、申请清单核验和画质提示；
- 无需已有申请即可进行不改库存的视觉试拍，方便现场演示；
- 借还照片入库前统一压缩并去除原始 EXIF 信息；
- 模型不支持的物资、画质异常或清单差异进入人工复核，不直接改库存；
- 借出照片入档后保留 AI 核验建议；当前版本所有正式借还均需管理员确认后更新库存；
- 管理员新增、编辑、停用物资，增减库存并记录原因及前后数量；
- 归还时报损或丢失，管理员复核后自动更新可用及缺损库存；
- systemd 常驻运行，Nginx 反向代理。

## 服务器

```bash
ssh sever1
sudo systemctl status warehouse-ai
sudo journalctl -u warehouse-ai -f
```

部署位置 `/opt/warehouse-ai`，共享数据库 `/opt/warehouse-ai/shared/warehouse.db`。

实时识别组合 [Ultralytics YOLOE-26s](https://docs.ultralytics.com/models/yoloe/) 与 [YOLO11n](https://docs.ultralytics.com/models/yolo11/)：`yoloe-warehouse.onnx` 包含 12 个英文物资提示词；`yoloe-megaphone.onnx` 使用红色喇叭实拍作视觉提示；`warehouse-specialist.onnx` 使用 23 张单品照及全部 8 张混放照微调，作为 10 类物资的演示专用检测器。训练样本和边界见 [training/README.md](training/README.md)。仓库内保留旧的 [YOLOv5n ONNX](https://github.com/ultralytics/yolov5/releases/tag/v7.0) 作为无新模型时的回退。照片差异仅是复核线索，不能据此自动判定损坏。服务器使用 `/opt/warehouse-ai/vision-venv` 中的 ONNXRuntime 运行模型。

2026-10-17 对 8 张混放照片逐物体标注并全部用于最终演示模型训练。组合模型在这批训练照片标出的 29 个目标里找出 28 个同类候选框（IoU≥0.3），漏掉 1 个手电筒。当前没有独立测试集，这不是新场景准确率，更不足以支持自动扣库；需要补拍独立场景照片评估泛化与误扣风险。
